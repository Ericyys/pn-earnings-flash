# 繪圖規範：通用規則＋各公司可調整的部分

## 為什麼要分開

每家公司的財報結構不同，以前遇到新公司只能回頭改程式或在核對第三層處理，底層邏輯一直變動，容易蓋掉原本設定好的規則。現在把出圖拆成兩層：

| 層 | 內容 | 誰改 | 存在哪裡 |
|---|---|---|---|
| **通用規則** | 選圖門檻、數字格式、年增率標示、配色版面、驗算、可用的計算方式清單 | 維護者（很少改） | 程式、`rules/triggers.json`、`rules/derivations.json`、`references/card_style.md` |
| **公司繪圖規範** | 這家公司「怎麼畫、怎麼算」：科目中文名稱、做哪幾張、用哪種算法、合併哪些列、調節項目 | 使用者在工具第 4 步「繪圖設定」調整 | `history/<市場>/<代號>/chart_rules.json` |

**套用順序：公司規範 > 通用預設。** 規範沒寫的項目一律用通用預設，所以新公司不用任何設定也能直接出圖；需要客製化時才調整，而且不必改程式。

## 三條界線

1. **核對只管原始數字。** 第一、二層確認原始數字無誤；第三層只列數據問題（抓錯、漏抓、單位與期間風險）。核對一律用通用預設計算，調整繪圖規範不會改變核對結果。
2. **規範只改呈現與計算方式，不改原始數字。** 所有圖卡數字都來自核對過的數據表。
3. **計算方式只能從清單中選。** 每一種都只用核對過的原始數字（清單見 `rules/derivations.json` 的 `company_options`），選了非預設的算法，圖卡頁尾會註明。

## 怎麼用

1. 第 3 步核對完成後，按「下一步：繪圖設定」。工具先用通用規則（加上這家公司已有的規範）產生圖卡。
2. 需要調整時在第 4 步修改，第 5 步的圖卡會立即更新。調整過的區塊會標「已調整」。
3. 按「下載繪圖規範」，把 `chart_rules.json` 上傳到 `history/<市場>/<代號>/`（同名檔案覆蓋）。
4. 下次這家公司出圖時，工具自動讀取這個檔案。

工具是靜態網頁，沒辦法自己寫回 GitHub，所以規範和本季存檔一樣要手動上傳。

## 可以調整的項目

| 區塊 | 項目 | 預設 |
|---|---|---|
| 科目中文名稱 | 每個科目在圖卡上的名稱。名稱依序採用：公司規範 → 公司設定檔 → 原文本身是中文 → 科目對照表 → AI 譯名。**AI 譯名要確認一次**（確認前不能下載圖卡），確認後記進規範 | 依上述順序 |
| 整組圖卡 | B 營收拆解、D 利潤率、G 現金流量：自動／一定要做／一定不做。「一定要做」不論是否觸發都產出，不佔自動選圖的 2 張 | 自動（依 `rules/triggers.json`） |
| 計算方式｜毛利 | 原文有就用原文、沒有就計算（預設）／只用原文／一律「營收 − 營業成本」／營業成本由指定費用列組成／不畫毛利 | 原文有就用原文 |
| 計算方式｜EPS 年增率 | 公司有寫且一致就用公司的（預設）／一律用公布 EPS 計算／用淨利 ÷ 股數 | 公司有寫就用 |
| 計算方式｜自由現金流 | 只用公司公布的（預設）／營業現金流 − 資本支出 | 只用公司公布的 |
| A1 封面 | 三個重點數字：營收、營益率、EPS、毛利率、淨利率、營業利益、淨利 | 營收、營益率、EPS |
| C 損益流向 | 每個節點標佔營收 %；合併指定的費用列（2 列以上）與合併後名稱 | 標示佔比；不合併 |
| B 營收拆解 | 維度（部門／地區）；哪些是調節項目；佔比低於幾 % 併為「其他」；標示佔比與位置（柱內／右側） | 自動維度；調節項目依公司設定檔或 AI 標示；不合併；柱內標佔比 |
| D 利潤率 | 顯示哪幾條（毛利率、營益率、淨利率） | 三條都顯示 |
| G 現金流量 | 顯示哪些項目（營業現金流、資本支出、自由現金流、庫藏股買回、現金股利） | 全部 |
| K1 財測 | 隱藏指定的財測項目 | 全部顯示 |

## 防呆

- **規範指到本季沒有的項目**（例如公司重編部門、費用列改名）：該項設定改用預設，並在繪圖設定頂端列出，不會默默畫錯。
- **繪圖檢查**：營收拆解卡依目前設定（調節項目、合併「其他」）重算「柱內加總＋註腳＝柱頂總額」，不通過不能下載圖卡。
- **規範檔格式不對的欄位一律忽略**，不會讓整個出圖失敗。
- 規範檔只記與通用預設不同的設定，容易看出這家公司調整了什麼；本季存檔也會記錄當季套用的規範。

## chart_rules.json 範例

```json
{
  "rules_version": "1.0",
  "ticker": "NFLX",
  "market": "us",
  "updated_at": "2026-11-02T08:00:00Z",
  "labels": { "opex:technology_and_development": "技術開發費用" },
  "deck": { "include": ["B"], "exclude": [] },
  "calc": { "gross_profit": "custom_cogs", "cogs_items": ["cost_of_revenue", "technology_and_development"] },
  "B": { "reconciling": { "hedging": true } }
}
```

項目代號：費用列 `opex:<key>`、部門 `seg:<key>`、地區 `geo:<key>`、財測 `guidance:<metric>|<原文名稱>`、財測調整 `revision:<metric>|<原文名稱>`、一次性項目 `notable:<原文名稱>`。`key` 來自數據表，同一家公司每季相同。
