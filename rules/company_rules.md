# 公司規範：各公司的財務算式與科目名稱

## 為什麼需要

通用流程（抽取 → 核對 → 選圖出圖）對每家公司都一樣，問題出在**每家公司新聞稿的算式不太一樣**：

- EPS 的分子：多數公司用歸屬母公司淨利；有特別股的公司用「歸屬普通股股東淨利」（淨利扣除特別股股利）。
- 毛利：有的公司把營業成本拆成好幾列（例如營業成本＋折舊攤銷），毛利＝營收−這幾列合計。
- 營收拆解：有部門、有地區；有的表裡同時列了小計和明細，有的有調節項目（Hedging、Corporate and other）。
- 自由現金流：各公司定義不同。

這些差異以前會在核對第三層反覆出現「不通過」，或讓圖卡數字和新聞稿對不上。現在把它們記在**這家公司的規範**裡，不改程式：

| 層 | 內容 | 誰改 | 存在哪裡 |
|---|---|---|---|
| 通用算式 | 預設的計算方式、選圖規則、數字格式、版面 | 維護者（很少改） | 程式、`rules/` |
| 公司規範 | 這家公司的算式、營收拆解的小計與調節項目、科目中文名稱 | 使用者在核對步驟的「公司規範」設定 | `history/<市場>/<代號>/company_rules.json` |

**公司規範同時套用在自動檢查與圖卡**：選對這家公司的算式後，勾稽不再誤報，圖卡數字也與新聞稿一致。規範沒寫的項目一律用通用算式，所以新公司不用設定也能直接用。

**要畫哪幾張圖卡不在規範裡**：一律由選圖規則（`rules/triggers.json`）決定；資料不完整（缺數字、加總不符）的圖卡不產出，條件圖卡由下一順位遞補。

## 怎麼設定

1. **第三層直接建議**：勾稽不通過時，工具會試著換成公司算式，相符就在「需要你判斷」顯示建議，例如：
   - 「改用歸屬普通股股東淨利計算為 1.2345，與原文相符：可能是這家公司的 EPS 算式不同」
   - 「把『折舊與攤銷』併進營業成本，毛利就與原文相符」
   - 「扣掉『交易收入合計』後加總就等於營收：這一列可能是小計」
   - 「用淨利 ÷ 股數算的 EPS 年增率與原文相符：這家公司用四捨五入前的數字計算」

   按「採用這個公司算式」就寫進規範並重算。不是算式問題（例如 AI 抓錯數字），照一般方式處理。
2. **手動設定**：核對步驟最後的「公司規範」區塊可以直接選算式、勾選調節項目與小計列、確認科目中文名稱。
3. **記住**：按「下載公司規範」，把 `company_rules.json` 上傳到 `history/<市場>/<代號>/`（同名覆蓋）。下次這家公司出圖時自動讀取。

## 可以設定的項目

| 項目 | 選項 | 預設 |
|---|---|---|
| EPS 的分子 | 歸屬母公司業主淨利／歸屬普通股股東淨利（原文有這一列就用原文，否則歸屬母公司淨利 − 特別股股利） | 歸屬母公司業主淨利 |
| 毛利 | 原文有就用原文、沒有就計算／只用原文／一律「營收 − 營業成本」／營業成本由指定的列組成／不畫毛利 | 原文有就用原文 |
| EPS 年增率 | 公司有寫且一致就用公司的／一律用公布 EPS 計算／用「EPS 的分子 ÷ 股數」計算 | 公司有寫就用 |
| 自由現金流 | 只用公司公布的／營業現金流 − 資本支出 | 只用公司公布的 |
| 營收拆解｜調節項目 | 勾選哪些是調節項目（不畫進柱子，兩期放註腳） | 公司設定檔或 AI 標示 |
| 營收拆解｜小計列 | 勾選哪些是小計（不計入加總、不畫） | 無 |
| 科目中文名稱 | 每個科目在圖卡上的名稱；AI 譯名要確認一次 | 公司設定檔 → 原文本身是中文 → 科目對照表 → AI 譯名 |

可選的算式也寫在 `rules/derivations.json` 的 `company_options`。每一種都只用核對過的原始數字；選了非預設的算式，圖卡頁尾會註明（例如「營業成本含折舊與攤銷」「EPS 年增率依歸屬普通股股東淨利 ÷ 稀釋股數計算」）。

## 防呆

- 規範只改「怎麼算」，不改原始數字。
- 規範指到本季不存在的項目（例如公司重編部門、費用列改名）時，那一項改用通用算式，並在「公司規範」區塊頂端列出。
- 規範檔格式不對的欄位一律忽略。
- 規範檔只記與通用算式不同的設定；本季存檔也會記錄當季套用的規範。

## company_rules.json 範例

```json
{
  "rules_version": "1.0",
  "ticker": "XYZ",
  "market": "us",
  "updated_at": "2026-11-02T08:00:00Z",
  "calc": { "eps_numerator": "common", "gross_profit": "custom_cogs", "cogs_items": ["cost_of_revenue", "depreciation_and_amortization"] },
  "revenue_items": { "reconciling": { "hedging": true }, "subtotal": ["transaction_based_revenues"] },
  "labels": { "opex:technology_and_development": "技術開發費用" }
}
```

項目代號：費用列 `opex:<key>`、部門 `seg:<key>`、地區 `geo:<key>`、財測 `guidance:<metric>|<原文名稱>`、財測調整 `revision:<metric>|<原文名稱>`、一次性項目 `notable:<原文名稱>`。`key` 來自數據表；兩個 AI 取的代號不同時，核對第三層會請你選正確的名稱，之後同一家公司就沿用。
