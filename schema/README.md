# 數據表規格說明

`fact_sheet.schema.json` 定義 AI 從財報抽出來的數據長什麼樣。網頁的核對、計算、選圖、出圖全部從這份數據讀取，所以它是整套工具的地基。

## 五條設計規則

1. **AI 只抄，不算。** 數據表裡只有原文出現的數字。年增率、利潤率、佔比全部由網頁計算。公司自己寫出的比率放在 `stated_metrics`，只拿來驗證網頁算得對不對。
2. **每個數字都附出處。** 表格數字必須附「列名＋欄名」，欄名要包含期間文字（例如 `Three Months Ended September 30, 2026`），抓錯欄一眼就看得出來。非表格數字附原句。沒附出處的數字，格式檢查就不會通過。
3. **照抄單位和正負號。** 仟元就寫仟元，括號就是負數。單位換算和正負號解讀由網頁依 `profiles/*.json` 處理，AI 不做任何轉換。
4. **沒有就填 null，不准估。** 原文沒有的數字填 `null` 並說明原因（未揭露／不適用）。格式不允許出現規格外的欄位，AI 加了「估計值」之類的欄位會直接被擋。
5. **需要人決定的才提出來。** 原文矛盾或不確定用哪一欄時，寫進 `ambiguities`，不要自己選；依規則已處理好的說明寫進 `notes`，不需要人工處理。

## 檔案分工

| 檔案 | 內容 | 誰改 |
|---|---|---|
| `schema/fact_sheet.schema.json` | 數據表格式 | 很少改，改了要同步更新抽取指令與網頁 |
| `profiles/us.json`、`profiles/tw.json` | 市場差異：單位、會計科目對照、正負號、檢查規則 | 遇到新的科目名稱時補上 |
| `companies/<市場>/<代號>.json` | 個別公司：財年、部門、KPI、同業 | 第一次追蹤時建立，公司重編部門時更新 |
| `rules/triggers.json` | 選圖門檻 | 試跑後校正 |
| `history/<市場>/<代號>/<季度>.json` | 核對完成的本季數據與核對紀錄 | 每次出圖後，從出圖工具下載「本季存檔」上傳 |

## 1.2 版新增

- `notes`：AI 依規則處理時的說明（核對畫面列在「自動處理」）。
- `guidance_revisions`：公司明確寫出調整前與調整後數字的財測上修／下修，K1 會列出。

## 1.3 版新增

- `meta.eps_basis`：抽取的 EPS 口徑（`diluted` 稀釋／`basic` 基本），圖卡標籤依此顯示。美股抽稀釋、台股抽基本；其他市場以新聞稿標題使用的 EPS 為準，並在 `meta.eps_basis_src` 附標題原句。
- `income_statement` 的 EPS 與股數只需填口徑對應的那一組（稀釋：`eps_diluted`＋`shares_diluted`；基本：`eps_basic`＋`shares_basic`）。
- `guidance_revisions[].previous_date`：原文寫出前次財測發布日期（月、日）時填 `M/D`，圖卡欄名顯示為「前次財測（M/D）」。

## 1.4 版新增

- `label_zh`：每個有 `label_source`（原文名稱）的項目都可以附中文名稱，由 AI 用台灣常用的財報用語翻譯。工具先用公司設定與科目對照表，對照表沒有時才用這個譯名，並列入核對第三層讓人確認。

## 1.5 版新增

- `segments[].reconciling`、`geographies[].reconciling`：調節項目（營收表中列在各部門小計之外、但計入總營收的項目，例如 Hedging、Corporate and other、Eliminations）填 `true`。營收拆解卡不畫進柱子、改放註腳；一般部門即使是負值也不填。

## 人工填寫的欄位

`consensus`（市場預期）不在財報裡，需人工從外部來源填入 JSON，必須附來源名稱、網址與日期。出圖工具目前沒有輸入市場預期的畫面，要在貼上前直接加進 JSON。
