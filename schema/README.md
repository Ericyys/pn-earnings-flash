# 數據表規格說明

`fact_sheet.schema.json` 定義 AI 從財報抽出來的數據長什麼樣。網頁的核對、計算、選圖、出圖全部從這份數據讀取，所以它是整套工具的地基。

## 五條設計規則

1. **AI 只抄，不算。** 數據表裡只有原文出現的數字。年增率、利潤率、佔比全部由網頁計算。公司自己寫出的比率放在 `stated_metrics`，只拿來驗證網頁算得對不對。
2. **每個數字都附出處。** 表格數字必須附「列名＋欄名」，欄名要包含期間文字（例如 `Three Months Ended September 30, 2026`），抓錯欄一眼就看得出來。非表格數字附原句。沒附出處的數字，格式檢查就不會通過。
3. **照抄單位和正負號。** 仟元就寫仟元，括號就是負數。單位換算和正負號解讀由網頁依 `profiles/*.json` 處理，AI 不做任何轉換。
4. **沒有就填 null，不准估。** 原文沒有的數字填 `null` 並說明原因（未揭露／不適用）。格式不允許出現規格外的欄位，AI 加了「估計值」之類的欄位會直接被擋。
5. **看不清楚就提出來。** 原文矛盾或不確定用哪一欄時，寫進 `ambiguities`，不要自己選。這裡的每一項都必須人工處理。

## 檔案分工

| 檔案 | 內容 | 誰改 |
|---|---|---|
| `schema/fact_sheet.schema.json` | 數據表格式 | 很少改，改了要同步更新抽取指令與網頁 |
| `profiles/us.json`、`profiles/tw.json` | 市場差異：單位、會計科目對照、正負號、檢查規則 | 遇到新的科目名稱時補上 |
| `companies/<市場>/<代號>.json` | 個別公司：財年、部門、KPI、同業 | 第一次追蹤時建立，公司重編部門時更新 |
| `rules/triggers.json` | 選圖門檻 | 試跑後校正 |
| `history/<市場>/<代號>/<季度>.json` | 核對完成的歷史數據 | 每次出圖後自動存檔 |

## 人工填寫的欄位

`consensus`（市場預期）不在財報裡，由 Ryan 從外部來源人工填寫，必須附來源名稱、網址與日期。
